# Project-format fixture provenance

These files are immutable compatibility evidence. Never regenerate or edit an
existing fixture after it has landed. A schema bump adds a new version-specific
fixture; it does not update an older one. `ProjectFixtureImmutabilityTest` pins
the exact bytes.

| Schema | Fixture | Provenance | Authentic serializer output? |
| --- | --- | --- | --- |
| v1 | `v1_minimal.aes` | Added in `f41829d6`, then hand-edited in `7bdb65b2` to exercise migration roundtrips. | No |
| v1 | `v1_rich.aes` and `v1_rich_assets/kick.wav` | Explicitly hand-authored in `f23e33aa` to cover rich v1 state and exact value fidelity. | No |
| v2 | `v2/serializer-v2-identity.aes` | Generated by building the last commit whose serializer wrote v2, `b4af8de2` (the parent of the v3 bump). Covers stable lane, clip, pattern, channel, and positional plugin-automation addressing. | Yes |
| v2 | `v2/serializer-v2-positional-mixer.aes` | Generated the same way, from `b4af8de2`. Covers the v2→v3 **topology** change: three lanes, two sharing a name, each paired positionally with a channel carrying distinct state. | Yes |
| v2 | `v2/serializer-v2-legacy-audio-split.aes` and `v2/legacy_audio_assets/shared.wav` | Generated the same way, from `b4af8de2`. Covers the loader-side **legacy audio split**: one audio pattern placed on two lanes. | Yes |
| v3 | `v3/serializer-v3-independent-mixer.aes` | Generated with the v3 serializer at the `ba80b605` starting tree. Covers independent playlist lanes/mixer channels and a missing-plugin placeholder with opaque state. | Yes |

The v2 fixture was produced from a temporary `git archive` of `b4af8de2`, with
a temporary generator linked to that revision's `ProjectSerializer.cpp`. The
archive was configured headlessly and the generator was built with `-j2`; only
the resulting `.aes` file was copied here. The generator deliberately created:

- one identified lane, pattern, and clip;
- one mixer channel;
- a plugin-parameter automation curve addressed by effect slot and parameter ID.

`v2/serializer-v2-positional-mixer.aes` was produced from a detached `git`
worktree at the same commit `b4af8de2`, configured headlessly
(`-DAESTRA_HEADLESS_ONLY=ON -DAESTRA_ENABLE_UI=OFF -DAESTRA_CI=ON`) and built
with `-j2`, using a temporary `Tests/GenerateV2TopologyFixture.cpp` target
linked against that revision's `ProjectSerializer.cpp`. Only the resulting
`.aes` file was copied here — it was **not** hand-edited, and its `version`
field was **not** altered; it reads `2` because that revision's serializer wrote
`2`.

It exists because the one-lane `serializer-v2-identity.aes` proves traversal but
cannot distinguish a correct lane↔channel pairing from a wrong one. v2 pairs
them **positionally** (`trackManager->getChannel(laneIndex)`) and writes channel
state into the lane object; v3 persists lanes and channels independently. The
generator therefore created:

- three lanes, of which **two share the name `"Shared Name"`** — a loader that
  pairs by name merges them;
- distinct lane-local volume/pan/mute/solo per lane, and distinct channel-only
  width/colour-index/input-index/solo-safe/armed per channel, so a merge, a swap
  or a positional collision changes at least one asserted value;
- routing that must survive as a separate concern: a pre-fader send from channel
  0 to channel 2, and a non-default main output on channel 1.

`ProjectCompatibilityPolicyTest` asserts the resulting v3 topology, routing and
state after load, then re-saves as v3 and reloads to prove save→load stability.

`v2/serializer-v2-legacy-audio-split.aes` was produced from the same detached
`b4af8de2` worktree, with the same headless configuration and a temporary
`Tests/GenerateV2LegacyAudioFixture.cpp` target. Not hand-edited; its `version`
field was not altered.

It pins a transformation the loader performs rather than a field the schema
changed. **The v2 serializer never writes `mixerChannelId` on a pattern** — the
token appears zero times in that revision's `ProjectSerializer.cpp` — so every
audio pattern in every v2 project is "legacy" to the v3 loader, where a pattern
owns its destination channel. The generator therefore created:

- one audio source (`legacy_audio_assets/shared.wav`, written by the generator,
  referenced by a relative path exactly as `v1_rich.aes` references its asset);
- **one** audio pattern;
- **two** lanes, each holding one clip that references that single pattern, each
  paired positionally with a channel carrying distinct colour/input-index state.

Loading it forces `clonePattern`: one pattern in the file becomes two in memory,
one per destination channel, and the second clip is repointed at the manufactured
pattern. Under the transformation contract this is not a no-op load, so it must
report `Transformed` and require saving. `ProjectCompatibilityPolicyTest` asserts
the split topology, the per-channel routing, the reported outcome and the dirty
decision, then proves the re-saved document reloads clean with no further split.

The v3 fixture was produced the same way with a temporary generator in the
current tree. Temporary generators are intentionally not retained as fixture
regeneration tools: future changes must preserve these bytes and add a new
fixture for a new schema.
