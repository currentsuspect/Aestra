feat(ui): one floating-panel descriptor table, with a headless registry guard (P5)

The geometry lookup and the panel lookup were two switches over the same
ViewType. Adding a floating panel meant editing both, and missing the second one
compiled clean and returned nullptr at runtime — the panel appeared with no
geometry and no persistence, with no warning anywhere.

They are now one row. `FloatingPanelDescriptor` carries the geometry AND a
pointer-to-member-function naming the panel, so there is no second place to
forget.

The panel members are five DIFFERENT derived types (MixerPanel, PianoRollPanel,
ArsenalPanel, AestraHistoryPanel, TakesPanel), so they cannot share a member
pointer. The options were friendship, std::function, or
pointer-to-member-function; the last is compile-checked, allocates nothing, and
keeps std::any and std::function out of the frame loop, which is what the plan
required. Five one-line accessors on AestraContent are the whole cost.

SCOPE, and what was deliberately left alone. The plan named four parallel
switches; this merges the first two. getViewOpenState and setViewOpen keep
theirs, because their per-panel behaviour is genuinely heterogeneous — the mixer
refreshes channels, the piano roll brings to front, the sequencer registers drop
targets, Playlist drives TrackManagerUI. A table would need a std::function per
panel for that: more ceremony than the switch, and it trades compile-time
checking for runtime dispatch. That objection was recorded before this work
started and it still holds.

ONE BEHAVIOUR CHANGE, and it is a bug fix. The old `default:` arm returned the
MIXER's geometry for anything unrecognised, so asking for Playlist — the
workspace, not an overlay — silently handed back the mixer's store key and size.
The lookup now returns nullptr for a non-floating view. The one caller that
wanted a fallback keeps it explicitly, logs which ViewType was missing, and says
so rather than defaulting quietly.

THE GUARD, which is the half that matters later.

PanelDescriptorRegistryTest asserts the registry is complete, derived from the
ViewType enum rather than a hand-written list, so adding an enum value changes
the arithmetic and the test notices. It also pins no duplicate rows, unique
non-empty store keys (two panels sharing a key overwrite each other's saved
geometry, which the surface store cannot report), and usable dimensions — a
zero default opens an invisible panel, which looks exactly like a panel that
failed to register, and that is the confusion this pass exists to remove.

It is deliberately headless: it includes only FloatingPanelDescriptors.h, which
has no UI dependency, because AESTRA_HEADLESS_ONLY skips the UI targets and no
test includes AestraContent.h. A registry guard that only ran in a lane most of
CI skips would be a guard that mostly does not run. Verified by configuring and
running it in a headless build, not assumed from the CMake placement.

That requirement is why the descriptor is split in two: geometry and identity
live in a header a headless build can read, and only the accessor pairing stays
in AestraContent.cpp because taking &AestraContent::mixerWindowFor needs the
class complete. A static_assert ties the two together, so a row with no accessor
is a compile error.

Negative control: deleted the History row, which is exactly "the next floating
panel that forgets to register". Two failures, naming History explicitly. Run to
completion before restoring — a control's exit code was masked by a pipe once
already this session, so it was re-checked directly.
