void Aestra::Audio::PatternPlaybackEngine::patternContentEdited ( )

Pattern content changed while playing (RT-safe producer-side flag).

Steps placed or removed in the Arsenal / Piano Roll call this instead of rewindScheduledInstances(): the next refill re-queues from the playhead with current note data — deletions silence immediately and additions enter at their exact frame — WITHOUT resetting the entry state. A full rewind here re-fired every currently-sounding note (audible flam on each edit) and made fresh placements sound before the playhead reached them (#823).

void Aestra::Audio::PatternPlaybackEngine::refillWindow ( uint64_t  currentFrame,
int  sampleRate,
int  lookaheadSamples = 4096,
uint64_t  loopLengthSamples = 0 
)

Refill lookahead window with events (non-RT thread) Called periodically by scheduler.

The live caller (AudioEngine::performNonRealtimeMaintenance) runs on the main loop and asks for a quarter second. Any UI stall longer than the lookahead lets the playhead pass the last queued hit, and the hits in between are skipped with no xrun (getSchedulingStats counts them). 4096 samples (~85 ms) was overtaken by ordinary slow frames, and the playhead the audio thread publishes trails by up to a buffer, so at 2048 the real lead was ~43 ms. Edits are not delayed by the longer window: any pattern change re-queues from the playhead.

Parameters
currentFrameCurrent transport frame. In looped pattern mode this is MONOTONIC (iteration * loopLengthSamples + wrapped position) so the window can pre-schedule the next iteration's events before the wrap — rewinding at the wrap and rescheduling on the next UI tick made every loop's downbeat land late by the maintenance latency.
sampleRateActive sample rate.
lookaheadSamplesNumber of frames to schedule ahead.
loopLengthSamplesLoop length in samples for looped pattern mode (loop start == 0); 0 = no loop (timeline / offline bounce).

Re-place a slot while playing without disturbing what already sounds (non-RT thread).

Like schedulePatternInstance(), but an existing slot keeps its scheduling frontier. schedulePatternInstance() resets it to 0, which wakes the refill's entry catch-up and re-fires every note already sounding. Pair with patternContentEdited(): the next refill re-queues this slot from the playhead at its new placement. Held notes that still span the playhead there carry on, and ones that no longer do are released at once. A slot that did not exist is scheduled fresh, exactly as by schedulePatternInstance().
