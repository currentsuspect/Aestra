Detailed Description

The Muse session loop: model proposes verbs, Muse executes them.

The loop is provider-agnostic and transport-agnostic. It bootstraps the tool manifest over the wire (get_schema), converts it into provider tool definitions, and iterates model → tool calls → Muse responses until the model calls finish, a budget is exhausted, or the user is needed.

Hard boundaries (the model must not decide success by vibes alone): max iterations, max tool calls, max elapsed time, and an explicit finish action carrying a summary.
