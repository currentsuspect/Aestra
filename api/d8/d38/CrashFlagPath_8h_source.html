4// Authoritative crash-flag path, resolved while platform utilities are alive
5// and retained for use during final shutdown (#675).
6//
7// The defect this exists to prevent: `AestraApp::shutdown()` clears the crash
8// flag LAST, deliberately, so that a crash during any earlier teardown step
9// leaves the flag behind for recovery. But `Platform::shutdown()` runs before
10// that final clear and destroys the platform utilities, and
11// `AestraApp::getAppDataPath()` silently falls back to the process working
12// directory when those utilities are gone. The clear therefore looked for
13// `<cwd>/crash_flag`, found nothing, and returned having done nothing — and
14// logged nothing either, because both its success and failure messages live
15// inside the `exists()` branch. Every clean exit left the flag behind, so every
16// next launch offered a spurious recovery.
17//
18// The ordering is correct and must not change. What must change is the path
19// resolution: resolve once, early, and reuse that exact string at the end.
20//
21// Deliberately a plain string holder with no dependency on Platform, the app,
22// or the filesystem, so the behaviour is unit-testable despite Source/ having
23// no linkable library target (#666).
24
