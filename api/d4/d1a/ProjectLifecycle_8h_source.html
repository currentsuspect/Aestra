4// Project lifecycle: the operations behind File > New / Open / Save, plus the
5// Muse host verbs that expose them.
6//
7// Two reasons this is its own file rather than more of AestraApp.cpp:
8//
9// * AestraApp.cpp is pinned at its exact line count by
10// Tests/Guards/file_size_baseline.txt, so a verb that needs the app's
11// private save/load path cannot be added there. A member function may be
12// defined in any translation unit, so the verbs live here and AestraApp.cpp
13// only loses the inline menu lambdas they replaced.
14// * The menu items and the verbs must run the SAME code. "New Project" as an
15// inline lambda was a dozen lines of stop / cleanup / reset / re-arm
16// autosave; a second copy for the agent would drift from the first the first
17// time either changed. Both now call AestraApp::createNewProject().
18//
19// A verb here is an application capability, not a UI gesture: `project.save`
20// takes a path, not "click Save As and type into the dialog". An agent cannot
21// drive a native file chooser, and a verb that needed one would be refused
22// headlessly for a reason that has nothing to do with the request.
