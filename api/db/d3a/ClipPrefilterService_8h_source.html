2// ClipPrefilterService — background computation of anti-aliased clip copies
3// (Phase 4, F1; design: Aestra-Internals: aestra-docs/clip-prefilter-lifecycle.md).
4//
5// Threading model (deliberately narrow):
6// * enqueue()/drainCompleted()/waitIdle() are called on the graph-build thread
7// (TrackManager::ensureClipPrefilters) or another non-audio thread.
8// * One lazily-started worker thread runs the pure ClipPrefilter math on job
9// data it OWNS (shared_ptr copies) — it never touches SourceManager/ClipSource
10// (their containers are not thread-safe), and it never runs on or blocks the
11// audio thread.
12// * On completion the worker invokes the (atomic-only) rebuild-request callback
13// so the app's graph pump picks the filtered copy up on its next drain.
