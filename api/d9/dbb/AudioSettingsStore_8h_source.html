4// One parser for audio_settings.conf (#649).
5//
6// The file previously had two independent readers that disagreed about what it
7// contained: AestraAudioController::loadSavedAudioSelection read `device` and
8// `input_device` and nothing else, while AudioSettingsPage::loadSettings read
9// all thirteen keys but could not apply any of them. That is why `samplerate`
10// and `buffersize` were persisted, displayed, and applied by nobody — the
11// reader that ran at startup did not know they existed.
12//
13// parse() and serialize() are stream-based and dependency-free so they can be
14// tested without a platform layer or a UI; only path resolution and the
15// convenience load()/save() wrappers live in the .cpp.

57// Presence is not sanity. kUnset rules out exactly one value (-1), so a
58// hand-edited or corrupted config can still carry 0 or a negative through
59// isSet() and reach a consumer. buffersize=0 is the dangerous one: it is a
60// divisor and an allocation size. A value outside these ranges carries no user
61// intent, so consumers treat it as absent and fall back to their default —
62// loudly, never silently.

66inline bool isPlausibleSampleRate(int v) { return v >= 8000 && v <= 768000; }
67
