144 // Host->child parameter changes. setParameter() only pushes onto this
145 // lock-free queue (no IPC, no lock, no allocation, never blocks); the worker
146 // thread (single consumer) drains it and forwards each change to the child as
147 // an ordered SETPARAM command, keeping the realtime callback free of parameter
148 // IPC (#238). The ring is SPSC: setParameter must be called from one producer
149 // thread. Today that is the UI/message thread — automation gates plugin-
150 // parameter curves to Internal-format plugins in AudioEngine, so the render
151 // thread never reaches OOP setParameter. Because the push itself never blocks,
152 // a future single RT producer (e.g. third-party automation, #467) would remain
153 // realtime-safe; adding a *second* concurrent producer would require an MPSC
154 // queue instead.
155 struct ParamChange {
156 uint32_t id{0};
157 float value{0.0f};
158 };
159 // Sized to comfortably absorb a full-preset burst (hundreds of distinct
160 // parameters applied in a tight loop) before the worker drains it.
161 static constexpr size_t kParamQueueCapacity = 4096;
162 // Cap per worker pass so a large burst against a slow child cannot monopolize
163 // the worker and starve PROCESS (which would make the RT callback fall back to
164 // audible passThrough). The remainder stays queued for the next pass.
165 static constexpr size_t kMaxParamDrainPerPass = 64;
166 LockFreeRingBuffer<ParamChange, kParamQueueCapacity> m_paramQueue;
167 std::atomic<uint64_t> m_paramDrops{0};
168
169 void drainParamQueueToChild();
