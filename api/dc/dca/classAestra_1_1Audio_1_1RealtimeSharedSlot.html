Detailed Description

template<typename T>
class Aestra::Audio::RealtimeSharedSlot< T >

A shared_ptr the audio thread can read without a lock.

In this C++17 build, std::atomic_load on a shared_ptr takes a mutex from a small global pool (libstdc++'s _Sp_locker), so every audio-thread read of an AtomicSharedPtr was a lock shared with every other shared_ptr atomic op in the process — a priority inversion waiting to happen. This slot keeps a few owned generations; a reader pins one with a reader count and gets a raw pointer, and the control thread only overwrites a generation nobody reads.

  • readRealtime(): any number of concurrent readers, any thread. Wait-free except for a retry when it races a publish. Never locks, never allocates, never drops the last reference.
  • publish() / owner(): control threads (serialised internally). publish() may yield while every spare generation is still pinned by a reader.

The pin is a store-then-load handshake on both sides (bump a count, re-read the index / store the index, read the counts), so those operations are seq_cst; acquire/release would let both sides read stale values.
