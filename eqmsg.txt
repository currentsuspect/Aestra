perf(realtime): annotate process() on AestraEQ

The last of the twelve. AestraEQ::process() now carries AESTRA_RT_NONBLOCKING,
so every allocation, lock and syscall on its audio-thread path is rejected at
compile time in CI rather than reviewed by eye. RT gate 35 TUs, suite 301/301.

I previously measured this as "~25 helpers and 5 hoists" and used it to justify
giving EQ its own PR. The 25 was wrong, and it is worth recording why: it counted
the intermediate accessors the gate named BEFORE the tables were hoisted. Five
static locals in the leaves made every caller transitively blocking, so clang had
to be told about each one. Hoist the leaves and clang infers the whole chain --
6 annotations total, not 25. The guarantee is identical either way; the earlier
number described an unhoisted intermediate state, not the size of EQ.

Five function-local `static constexpr` tables hoisted to class scope as
`inline static constexpr`, and renamed to UPPER_SNAKE_CASE per AGENTS.md §9
(K_LEGACY_BAND_SLOTS, K_TYPE_CHOICES, K_DYNAMIC_TYPE_CHOICES, K_STEREO_MODES,
K_SLOPES_DB_PER_OCT) -- §9 was enforced on #1020 and there was no reason to hand
CodeRabbit the same finding twice. The two filter-type tables are deliberately
kept separate rather than merged: the legacy band's list is 4 entries indexed
x3.0, the dynamic band's is 8 indexed x7.0.

Negative control, run twice: injecting `new float[1]` into AestraEQ::process()
failed the gate naming AestraEQ.h:537, exit 1. Run twice on purpose -- the first
pass came back green and I did not believe it, because the same file and line
had failed moments earlier. The second run proved the gate was live and
recompiling rather than stale, which is the only thing that distinguishes a real
pass from a cached one. Both runs removed by exact-text edit and verified with
an explicit grep for the marker, never `git checkout` -- see below.
