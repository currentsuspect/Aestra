CRITICAL FIXES
================================================================================

[FIX] AuditionEngine: Eliminate mutex in RT audio callback path
  
  Problem:
    - processBlock() called from RT thread accessed m_currentSource
    - UI thread held m_queueMutex during file I/O and allocations
    - Priority inversion risk + potential audio dropouts
    - CRITICAL: Raw pointer approach had use-after-free race
  
  Solution:
    - Use C++17 atomic shared_ptr (std::atomic_load/store_explicit)
    - RT thread: atomic load bumps refcount, keeps object alive
    - UI thread: atomic store, old object destructs safely
    - No raw pointers, no manual lifetime management
  
  Files:
    M AestraAudio/include/Playback/AuditionEngine.h
    M AestraAudio/src/Playback/AuditionEngine.cpp
  
  Impact:
    + Zero blocking in RT callback
    + Eliminates priority inversion
    + Automatic refcount-based lifetime (no use-after-free)
    + Explicit memory ordering
    - No API changes
    - No performance regression
