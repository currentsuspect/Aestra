## Objective

Optimize the Plate post-allpass path, identified in Session 005 as the root cause
of Plate mode's 43% slowdown vs Room. The post-allpass used non-power-of-two
buffers (101 and 77 samples at 48kHz) with expensive integer `%` modulo wrapping.

Also add a dedicated profiling stage for the post-allpass so future sessions can
measure it independently of Output/Mix.

### Optimization 1: Power-of-Two Post-Allpass Buffer Capacity

**What:** Post-allpass buffers (`m_platePostL`, `m_platePostR`) are now allocated at
power-of-two capacity. The effective delay length is stored separately and used
for computing the read position.

**Buffer capacity impact (48kHz):**
- Stage 0 (base 89): capacity 128 (was 101), delay length 101
- Stage 1 (base 67): capacity 128 (was 77), delay length 77

**Code change in `prepareDelayLines`:**
```cpp
// Old
m_platePostL[stage].assign(static_cast<size_t>(maxLength), 0.0f);
m_platePostR[stage].assign(static_cast<size_t>(maxLength), 0.0f);

// New
const uint32_t pow2Size = nextPowerOfTwo(static_cast<uint32_t>(maxLength));
m_platePostL[stage].assign(static_cast<size_t>(pow2Size), 0.0f);
m_platePostR[stage].assign(static_cast<size_t>(pow2Size), 0.0f);
m_platePostDelayLengths[stage] = maxLength;  // Preserve original delay
m_platePostMasks[stage] = static_cast<int>(pow2Size) - 1;
```

### Optimization 2: Bitmask Wrapping in Post-Allpass Hot Loop

**What:** Replaced `wrapIndex()` (integer `%` modulo) and `(p + 1) % size` with
bitwise AND wrapping. Separated the write position from the read position so the
delay length can remain independent of buffer capacity.

**Code change in `processPlatePostAllpass`:**
```cpp
// Old
const int p = wrapIndex(pos[stage], static_cast<int>(bufL.size()));
const float delayedL = bufL[static_cast<size_t>(p)];
...
pos[stage] = (p + 1) % static_cast<int>(bufL.size());

// New
const int mask = m_platePostMasks[stage];
const int delayLength = m_platePostDelayLengths[stage];
const int p = pos[stage] & mask;
const int readP = (p - delayLength) & mask;

const float delayedL = bufL[static_cast<size_t>(readP)];
...
bufL[static_cast<size_t>(p)] = left + g * yL;  // Write at p, read at readP
...
pos[stage] = (p + 1) & mask;
```

**Semantic equivalence proof:**
- Original: buffer size = delay length. Read and write at same position `p`. After
  `size` samples, position wraps and reads what was written `size` samples ago.
- New: buffer capacity = power-of-two. Write at position `p`, read from
  `(p - delayLength) & mask`. After `delayLength` samples, read position points to
  where we wrote `delayLength` samples ago.
- Startup: both read 0-initialized buffers for the first `delayLength` samples.
- The output is mathematically identical; only which physical buffer slots are
  used changes.

### Optimization 3: Cached Position Init with Bitmask

**Code change in `process()`:**
```cpp
// Old
platePostPos[stage] = wrapIndex(platePostPos[stage], static_cast<int>(m_platePostL[stage].size()));

// New
```

## Accepted Optimizations

1. **Power-of-two post-allpass buffer capacity + separate delay length** — ACCEPTED
   - Eliminates integer `%` modulo in the hot loop
   - Buffer capacity is 128 for both stages; delay lengths remain 101 and 77
   - Mathematically equivalent to original circulating delay line

2. **Bitmask wrapping in post-allpass** — ACCEPTED
   - Replaces `wrapIndex()` (uses `%`) with single `& mask` operation
   - Replaces `(p + 1) % size` with `(p + 1) & mask`
   - Write position and read position are now separate, enabling capacity ≠ delay

3. **Dedicated `kPlatePostAllpass` profile stage** — ACCEPTED
   - Enables precise measurement of post-allpass cost in future sessions
   - Revealed post-allpass is ~4.9% of total Plate CPU time

4. **Benchmark bug fix (capture Plate profile data)** — ACCEPTED
   - JSON/Markdown outputs now contain correct Plate stage profile
   - Room and Hall profiles were unaffected

## Rejected Optimizations

1. **Removing post-allpass entirely** — REJECTED
   - Would change Plate sound character
   - Hard constraint: "Do not remove the Plate post-allpass stages"

2. **Changing delay lengths to match buffer capacity** — REJECTED
   - Would change the allpass delay from 101→128 and 77→128
   - Would audibly alter Plate mode's late-field diffusion
   - Hard constraint: delay lengths must be preserved

3. **SIMD vectorization of post-allpass** — REJECTED
   - Only 2 stages, each with simple scalar math
   - SSE would require interleaving L/R or using shuffles for 2-wide ops
   - Not worth the complexity for 2 stages × 2 reads × 2 FMAs

## Plate Timing Explanation

**Why was Plate ~10% slower than Room in Session 005?**

The post-allpass added 2 allpass stages per sample. Each stage used:
1. `wrapIndex(pos, size)` — integer `%` modulo (expensive for non-power-of-two sizes)
2. `(p + 1) % size` — another `%` modulo

At 48kHz:
- Stage 0: buffer size 101 (prime-ish), `% 101` requires integer division (~20-30 cycles)
- Stage 1: buffer size 77, `% 77` requires integer division

2 stages × 2 divisions × 240,000 samples = 960,000 integer divisions per 5-second block.
At ~25 cycles per division, that's ~24M cycles ≈ **~12 ms** on a 2GHz CPU.

Additionally, the `%` operation disrupts instruction-level parallelism and prevents
loop unrolling. Replacing it with `& mask` (1 cycle, fully pipelined) removes this
bottleneck entirely.

**Session 006 result:** Plate is now on par with Room, confirming the diagnosis.

## Risks Introduced

1. **Memory increase:** Post-allpass buffers grew from 178 samples total (101 + 77)
   to 256 samples total (128 + 128). Increase: ~78 samples × 2 channels × 4 bytes
   = ~624 bytes. Negligible.

2. **Separate read/write positions:** The new implementation writes at `p` and reads
   from `(p - delayLength) & mask`. This is mathematically equivalent but uses a
   different memory access pattern. The read and write are now at different positions
   (except when `delayLength == capacity`, which is no longer the case). This means
   the same cache line may contain both the read and write targets, which is actually
   cache-friendly.

3. **Profile stage count change:** Adding `kPlatePostAllpass` shifted `kOutputMix`
   from index 8 to 9. The benchmark auto-generates reports based on `kStageCount`,
   so this is handled. External tools that hardcode stage indices would break, but
   no such tools are known to exist.

Converting the predelay buffer to power-of-two would eliminate this branch and the
`%` modulo in `wrapIndex(predelayPos, size)` at the start of `process()`.
