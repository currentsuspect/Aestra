## Workflow Design

### Triggers
- `workflow_dispatch` — manual runs
- `push` to `develop` — when reverb/DSP code changes
- `pull_request` — when reverb/DSP code changes

### Runner
- `ubuntu-24.04` — pinned to reduce image drift

### Benchmark Matrix (per run)
1. **Runtime Dispatch** (Cubic + best available SIMD) — always runs
2. **Scalar Fallback** (Cubic + Scalar) — always runs
3. **Linear + Scalar** (original baseline) — always runs
4. **AVX2** — SKIPPED with note if runner lacks AVX2, RUN if available

### Outputs
- `labs/reverb/ci-output/cpu-metadata.txt` — full system info
- `labs/reverb/ci-output/benchmark-*.json` — structured results per config
- `labs/reverb/ci-output/benchmark-*.md` — markdown reports
- `labs/reverb/ci-output/benchmark-*.txt` — console capture
- `labs/reverb/ci-output/comparison-report.md` — side-by-side comparison
- `labs/reverb/ci-output/avx2-status.txt` — AVX2 run/skip status

### Failure Conditions
- Build errors → FAIL
- Benchmark crash → FAIL
- NaN/Inf in output → FAIL
- Missing artifact → does not fail (advisory)
- AVX2 not available → does NOT fail (reports SKIPPED)

### GitHub Step Summary
- CPU detection results
- AVX2 status (RUN or SKIPPED)
- Comparison table
- Link to artifacts
