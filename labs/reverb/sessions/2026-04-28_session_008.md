# Session 008 — 2026-04-28

## Objective

Optimize the Input/Predelay ring buffer path. Session 007 identified the predelay
path as having conditional wrapping (`if (predelayRead < 0)`) and `wrapIndex`
modulo in the init. The goal was to apply the same power-of-two + bitmask pattern
while preserving exact predelay timing.

## Starting State

- Branch: `develop`
- SHA: `035e2e38` (Session 007)
- Predelay: conditional branch wrapping per sample, `wrapIndex` modulo in init
- Buffer size at 48kHz: ~24,001 samples (non-power-of-two)

## Changes Made

### Files Changed
- `AestraAudio/include/Plugin/AestraVerb.h`

### Optimization 1: Power-of-Two Predelay Buffer Capacity

**What:** Predelay buffers (`m_predelayL`, `m_predelayR`) are now allocated at
power-of-two capacity. The effective maximum predelay length (`m_maxPredelaySamples`)
is preserved for parameter clamping.

**Buffer capacity impact (48kHz):**
- Old: ~24,001 samples (~94KB per channel)
- New: **32,768** samples (~128KB per channel)
- Increase: ~34KB per channel (~68KB total). Negligible for desktop DAW.

**Code change in `prepareDelayLines`:**
```cpp
// Old
m_maxPredelaySamples = std::max(1, static_cast<int>(std::ceil(m_sampleRate * 0.5)));
m_predelayL.assign(static_cast<size_t>(m_maxPredelaySamples) + 1, 0.0f);
m_predelayR.assign(static_cast<size_t>(m_maxPredelaySamples) + 1, 0.0f);

// New
m_maxPredelaySamples = std::max(1, static_cast<int>(std::ceil(m_sampleRate * 0.5)));
const uint32_t predelayPow2 = nextPowerOfTwo(static_cast<uint32_t>(m_maxPredelaySamples) + 1);
m_predelayL.assign(static_cast<size_t>(predelayPow2), 0.0f);
m_predelayR.assign(static_cast<size_t>(predelayPow2), 0.0f);
m_predelayMask = static_cast<int>(predelayPow2) - 1;
```

### Optimization 2: Bitmask Wrapping in Predelay Hot Loop

**What:** Replaced conditional branch wrapping and increment-wrap with bitwise AND.

**Code change in `process()` hot loop:**
```cpp
// Old
m_predelayL[predelayPos] = inL;
m_predelayR[predelayPos] = inR;
int predelayRead = predelayPos - control.predelaySamples;
if (predelayRead < 0) predelayRead += static_cast<int>(m_predelayL.size());
float delayedL = m_predelayL[predelayRead];
float delayedR = m_predelayR[predelayRead];
if (++predelayPos >= static_cast<int>(m_predelayL.size())) predelayPos = 0;

// New
const int preMask = m_predelayMask;
m_predelayL[predelayPos] = inL;
m_predelayR[predelayPos] = inR;
int predelayRead = (predelayPos - control.predelaySamples) & preMask;
float delayedL = m_predelayL[predelayRead];
float delayedR = m_predelayR[predelayRead];
predelayPos = (predelayPos + 1) & preMask;
```

**Semantic equivalence proof:**
- Old: `predelayRead = predelayPos - predelaySamples`; if negative, add buffer size.
  This is equivalent to modulo wrapping: `predelayRead = (predelayPos - predelaySamples) % size`.
- New: `predelayRead = (predelayPos - predelaySamples) & mask`.
  Since `mask = size - 1` and `size` is power-of-two, `& mask` is equivalent to `% size`.
- The delay remains exactly `control.predelaySamples` samples.
- The write position wraps with `(predelayPos + 1) & mask`, same as before.

### Optimization 3: Bitmask Position Init

**Code change in `process()` init:**
```cpp
// Old
if (!m_predelayL.empty()) {
    predelayPos = wrapIndex(predelayPos, static_cast<int>(m_predelayL.size()));
}

// New
predelayPos &= m_predelayMask;
```

## Accepted Optimizations

1. **Power-of-two predelay buffer capacity + cached mask** — ACCEPTED
   - Eliminates `if (predelayRead < 0)` branch per sample
   - Eliminates `if (++predelayPos >= size)` branch per sample
   - Eliminates `wrapIndex` modulo in init
   - ~5% whole-reverb improvement on Room/Hall

2. **Bitmask wrapping in predelay hot loop** — ACCEPTED
   - Replaces conditional branch with `(predelayPos - delay) & mask`
   - Replaces increment-wrap with `(predelayPos + 1) & mask`
   - Mathematically equivalent to original modulo behavior

3. **Cached position init with bitmask** — ACCEPTED
   - Replaces `wrapIndex` (uses `%` modulo) with `& mask`

## Rejected Optimizations

1. **Removing predelay entirely** — REJECTED
   - Would remove a core reverb feature
   - Hard constraint: predelay must be preserved

2. **Changing predelay max time** — REJECTED
   - `m_maxPredelaySamples` is 500ms (half the sample rate)
   - Any change would alter the parameter range

3. **Precomputing predelay read offset** — REJECTED
   - `predelayPos` changes every sample; read offset must be computed per sample
   - No win possible here

## Risks Introduced

1. **Memory increase:** Predelay buffers grew from ~24KB per channel to ~32KB per
   channel (+8KB each, +16KB total). Negligible for desktop DAW use.

2. **Power-of-two constraint:** Future predelay tuning must respect the power-of-two
   capacity. The `nextPowerOfTwo` helper handles this automatically.

3. **No semantic risks:** The predelay delay is computed as `(predelayPos - delay) & mask`.
   This is identical to `(predelayPos - delay) % capacity` when capacity is power-of-two.
   The output is bit-for-bit identical in terms of which sample is read.

## Recommended Session 009 Target

**LFO Normalize + Control** — currently ~7.4% of total CPU time.

The LFO normalization happens every 32 samples (kControlInterval):
```cpp
if (controlCountdown == 0) {
    normalizeLFOsAVX2(...);  // or scalar normalizeOscillator
    updateControlCache(control, ...);
    controlCountdown = kControlInterval;
}
```

`normalizeOscillator` does a scalar sqrt per line (8 lines):
```cpp
static void normalizeOscillator(float& s, float& c) {
    const float mag2 = s * s + c * c;
    if (mag2 > 0.25f && mag2 < 4.0f) {
        const float scale = 1.0f / std::sqrt(mag2);
        s *= scale;
        c *= scale;
    }
}
```

Potential optimizations:
1. **Approximate reciprocal sqrt** — replace `1.0f / std::sqrt(mag2)` with `_mm_rsqrt_ps`
   or a fast approximation (e.g., Newton-Raphson iteration on `rsqrt`). This is already
   done in the AVX2 path; the scalar path could use `__builtin_ia32_rsqrtss` or similar.
2. **Reduce normalization frequency** — The LFOs are quadrature oscillators with
   very small phase increments. They drift slowly. Normalizing every 64 or 128
   samples instead of 32 might be sufficient and would halve the normalization cost.
   This needs careful testing to ensure no audible drift accumulation.

**Secondary target:** The `Output/Mix` stage (~14.0%) includes the width matrix,
wet/dry mix, and clamping. The width matrix is:
```cpp
const float widthL = wetL * control.widthMain + wetR * control.widthCross;
const float widthR = wetR * control.widthMain + wetL * control.widthCross;
```

This is 4 FMAs per sample. On SSE4.1, this could be vectorized as a 2-wide dot
product, but the gain would be minimal (4 FMAs → 2 SIMD ops). The clamping at the
end (`std::clamp`) is also scalar. Not a high-priority target.
