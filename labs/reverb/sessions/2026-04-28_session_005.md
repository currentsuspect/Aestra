### Optimization 1: Power-of-Two Early Reflection Buffers + Bitmask Wrapping

**What:** The left/right early reflection ring buffers (`m_earlyL`, `m_earlyR`)
are now allocated at power-of-two sizes. All wrapping in the 12-tap read loop
uses bitwise AND with `(size - 1)` instead of conditional branches.

**Buffer size impact (48kHz):**
- Old: ~6,720 samples → ~54KB per channel
- New: 8,192 samples → ~64KB per channel
- Increase: ~20KB total (10KB per channel). Negligible.

**Code change in `prepareDelayLines`:**
```cpp
// Old
const int earlyMaxSamples = std::max(2, static_cast<int>(std::ceil(m_sampleRate * 0.14)));
m_earlyL.assign(static_cast<size_t>(earlyMaxSamples), 0.0f);
m_earlyR.assign(static_cast<size_t>(earlyMaxSamples), 0.0f);

// New
const int earlyMaxSamples = std::max(2, static_cast<int>(std::ceil(m_sampleRate * 0.14)));
const uint32_t earlyPow2 = nextPowerOfTwo(static_cast<uint32_t>(earlyMaxSamples));
m_earlyL.assign(static_cast<size_t>(earlyPow2), 0.0f);
m_earlyR.assign(static_cast<size_t>(earlyPow2), 0.0f);
m_earlyMask = static_cast<int>(earlyPow2) - 1;
```

**Code change in `processEarlyReflections`:**
- Old: 24 conditional branches per sample (12 taps × 2 `if (readX < 0) readX += ringSize`)
- Old: `if (++pos >= ringSize) pos = 0;` at the end
- Old: `pos = wrapIndex(pos, ringSize);` at the start (uses `%` modulo)
- New: single bitmask at start (`pos &= mask`), then all 12 taps use `& mask`:
  ```cpp
  for (size_t tap = 0; tap < kEarlyTapCount; ++tap) {
      const int readL = (pos - control.earlyDelayL[tap]) & mask;
      const int readR = (pos - control.earlyDelayR[tap]) & mask;
      // ... accumulate
  }
  pos = (pos + 1) & mask;
  ```

**Code change in `process()` earlyPos init:**
- Old: `earlyPos = wrapIndex(earlyPos, static_cast<int>(m_earlyL.size()));`
- New: `earlyPos &= m_earlyMask;`

### Optimization 2: Removed Redundant `ringSize` Local Variable

**What:** The old code loaded `m_earlyL.size()` into a local `ringSize` variable
and passed it to `wrapIndex`. The new code uses the cached `m_earlyMask` directly.

**Why:** Fewer instructions in the hot path, one less variable to track.

### Optimization 3: Made Tap Indices `const`

**What:** `readL` and `readR` are now `const int` within the tap loop.

**Why:** Signals to the compiler that these values won't alias or change,
potentially enabling better instruction scheduling.

### Why the Improvement is Modest (~7.5% stage, ~1.8% overall)

The early reflection tap loop is relatively simple: 12 iterations, each doing
2 memory reads, a few multiplies, and 2 accumulates. Modern CPUs predict the
`if (readX < 0)` branches very well because the pattern is regular (tap offsets
are fixed, write position advances by 1 each sample). The branch misprediction
rate is low.

The main win is eliminating the `%` modulo in `wrapIndex(pos, ringSize)` at the
start of each `processEarlyReflections` call, plus removing the 24 conditional
branches that still consume frontend bandwidth even when correctly predicted.

On a CPU with weaker branch prediction or under higher load (e.g., many plugins
running simultaneously), the bitmask approach would show a larger relative win.

## Plate Mode Timing Investigation

### Session 004 Non-Profile Benchmarks (Clean Run)

| Mode | Time | vs Room |
|------|------|---------|
| Room | 110.0 ms | 1.00x |
| Hall | 118.6 ms | 1.08x |
| Plate | 157.8 ms | **1.43x** |

Plate was **43% slower** than Room. Why?

### Analysis

**1. Early Reflections do NOT contribute to Plate's extra cost.**

The early reflection path is identical across all modes:
- Same 12 taps
- Same buffer size (power-of-two, ~8,192 samples)
- Same loop structure
- The only mode-specific data is `earlyDelayL/R` and `earlyGains`, which are
  precomputed in `ControlCache` and don't affect loop cost.

**2. The Plate-specific overhead is `processPlatePostAllpass`.**

Plate mode calls this function in the Output/Mix stage:
```cpp
void processPlatePostAllpass(float& left, float& right,
                             std::array<int, kPlatePostAllpassCount>& pos) {
    const float g = 0.6f;
    for (size_t stage = 0; stage < kPlatePostAllpassCount; ++stage) {
        // ...
        const int p = wrapIndex(pos[stage], static_cast<int>(bufL.size()));
        // ... 2 reads, 2 FMAs, 2 writes ...
        pos[stage] = (p + 1) % static_cast<int>(bufL.size());
    }
}
```

This adds **2 allpass stages per sample**, each with:
- `wrapIndex()` (integer modulo `%`)
- 2 memory reads
- 2 FMAs
- 2 memory writes
- Another `%` modulo for position increment

**3. The post-allpass buffer sizes are NOT power-of-two.**

At 48kHz:
- Stage 0: `ceil(89 * 1.0) + 4 = 93` samples
- Stage 1: `ceil(67 * 1.0) + 4 = 71` samples

Both 93 and 71 are prime-ish numbers. The `% 93` and `% 71` operations are
**expensive integer divisions** that cannot be optimized to bitwise AND.

**4. The Output/Mix stage bears this cost.**

In the profile data, Output/Mix is ~6.8% of total time. But this is for Room
mode (no post-allpass). For Plate mode, the post-allpass would add roughly:
- 2 stages × (2 reads + 2 writes + 2 FMAs + 2 divisions) per sample
- At 48kHz over 5 seconds: 240,000 samples × 2 stages = 480,000 iterations
- Integer division on x86 is ~20-30 cycles. Two divisions per stage = ~40-60 cycles.
- 480,000 × 40 cycles ≈ 19M cycles ≈ **~6-10 ms extra** on a 2GHz CPU

This alone doesn't explain the full 43% gap (47ms), but combined with:
- The post-allpass memory accesses being scattered (non-contiguous buffers)
- Cache pressure from additional buffers
- The `%` modulo disrupting instruction-level parallelism

…it is the dominant contributor. The FDN delay lines in Plate mode are actually
**shorter** than Room/Hall (677-1013 vs 1116-1617), so the FDN path is cheaper.
The post-allpass is what makes Plate expensive.

**Conclusion:** Early Reflections are NOT the cause of Plate's slowness.
The `processPlatePostAllpass` function with its non-power-of-two buffers and
expensive `%` modulo operations is the culprit.

## Accepted Optimizations

1. **Power-of-two early reflection buffers + bitmask wrapping** — ACCEPTED
   - Eliminates 24 conditional branches per sample
   - Eliminates `%` modulo in `wrapIndex`
   - ~7.5% improvement in Early Reflections stage
   - ~20KB memory increase (negligible)

2. **Cached `m_earlyMask` member** — ACCEPTED
   - Avoids recomputing `size - 1` or querying `m_earlyL.size()`
   - Applied to both `process()` init and `processEarlyReflections`

3. **`const` tap indices** — ACCEPTED
   - Cleaner code, better compiler hints
   - No downside

## Rejected Optimizations

1. **SIMD early reflection accumulation** — REJECTED
   - Each tap reads from the same two buffers (`m_earlyL`, `m_earlyR`) at
     different offsets. A SIMD gather would require loading 4 offsets,
     computing 4 addresses, and doing 4 scalar gathers — which is slower than
     4 scalar loads on SSE4.1 without AVX2 gather instructions.
   - The accumulation is also interleaved (earlyL depends on both L and R reads),
     making horizontal reduction messy.
   - Prompt explicitly warned: "prefer scalar-but-cache-clean over fake vectorization"

2. **Precomputing `pos - earlyDelay` in ControlCache** — REJECTED
   - `pos` changes every sample (increments by 1). Precomputing absolute read
     positions in ControlCache would require updating them every sample anyway,
     which is the same cost as computing `pos - delay` on the fly.
   - Precomputing relative offsets (just `earlyDelayL/R`) is already done.

3. **Optimizing Plate post-allpass** — REJECTED (deferred to Session 006)
   - Would change Plate buffer sizes (power-of-two rounding)
   - Would change position wrapping behavior
   - The prompt explicitly said: "Do not change Plate sound in this session"
   - Identified as the root cause of Plate slowness, recommended for next session

## Risks Introduced

1. **Memory increase:** Early reflection buffers grew from ~13.4KB to ~16KB per
   channel (+2.6KB each, +5.2KB total). Negligible for desktop DAW use.

2. **Power-of-two constraint:** Future early reflection tuning must respect the
   power-of-two buffer size. The `nextPowerOfTwo` helper ensures this automatically.

3. **Mask vs size semantics:** `m_earlyMask` is `size - 1`. Any code that needs
   the actual size must use `m_earlyL.size()` or `m_earlyMask + 1`. The `empty()`
   check was replaced with `m_earlyMask <= 0` which is equivalent (mask == 0 when
   buffer size is 1 or 0).

## Recommended Session 006 Target

**Plate Post-Allpass** — the root cause of Plate mode's 43% slowdown.

`processPlatePostAllpass` uses:
1. `wrapIndex()` (integer `%` modulo) at the start of each stage
2. Another `%` modulo for position increment: `(p + 1) % bufL.size()`
3. Non-power-of-two buffer sizes (93 and 71 at 48kHz)

Recommended optimizations:
1. Round post-allpass buffers to next power-of-two
2. Replace `wrapIndex` and `%` with bitmask wrapping
3. Apply the same pattern to `m_platePostL`, `m_platePostR`, and their positions

This should close most of the 43% gap between Plate and Room modes.

**Secondary target:** If Plate post-allpass is insufficient, investigate the
`processDiffusers` path. The diffuser loop has conditional wrapping:
```cpp
if (p >= len) p = 0;
```
And the diffuser buffers are not power-of-two. Converting them would follow the
same pattern as Sessions 004 and 005.
