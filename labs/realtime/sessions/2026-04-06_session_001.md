First session of the realtime lab. Created diagnostic test that confirms the
known bug: audio thread runs SCHED_OTHER, not SCHED_FIFO/SCHED_RR.

## Diagnostic Results

| Check | Value | Status |
|-------|-------|--------|
| Scheduling policy | SCHED_OTHER (0) | ❌ Bug confirmed |

| RLIMIT_RTPRIO | 0/0 | ❌ No RT capability |

| SCHED_RR range | 1–99 | ✅ Valid range |

## Key Findings

1. **No CAP_SYS_NICE** — `RLIMIT_RTPRIO=0` means RT scheduling requires root or
   capabilities. This is a deployment issue, not a code issue.
2. **8MB memlock limit** — `mlockall` should work for typical audio buffer sizes
   (8MB is plenty for audio processing).
3. **Fix requires capabilities** — To set SCHED_FIFO, the process needs either
   `CAP_SYS_NICE` or `RLIMIT_RTPRIO > 0`.
