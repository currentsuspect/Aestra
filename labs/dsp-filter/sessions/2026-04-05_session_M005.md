# DSP Filter Lab Optimization Session M005

## Purpose

Optimize the `processBlock()` hot path by eliminating per-sample branch checks.

## Baseline

- Hard gate: `./labs/dsp-filter/run_eval.sh` -> `accept` (exit code 0)
- Commit: `24fd97cb` (develop)
- Last change: M004 settled-state short-circuit in `updateInternal()`

## Rounds

### Round 1 — Accept

- Hypothesis: Dispatch the processing variant (drive × oversampling) once per
  block instead of checking `m_drive` and `m_oversampling` per sample.
- Implementation: Split `processBlock()` into four specialized loops:
  1. Fast path: no drive, no oversampling (tight `processSample()` loop)
  2. Drive only: apply saturation then `processSample()`
  3. Oversampling only: `processOversampled()` per sample
  4. Both: saturation + oversampling per sample
- Result: hard gate passed (`AestraFilterTest` exit code 0)
- Action: kept. Committed as `dsp-filter-lab: accept round M005 dispatch processing variant once per block`

## Outcome

- Accepted change: per-block dispatch in `processBlock()` eliminates two
  per-sample branch checks. The common case (no drive, no oversampling) is now
  a tight loop with only `processSample()` calls and zero branches.
- Remaining optimization surface: `processBlockStereo()` has the same
  per-sample branch pattern and could benefit from the same treatment.
