## Key Observations

1. **Dispatch overhead dominates** — the `switch (numTaps)` or `if (numTaps <= 4)`
   branches in the stereo output path add per-output-sample overhead that outweighs
   any loop-unroll benefit for tap counts >= 8. Only Linear (2 taps) improved (-21%).
2. **Existing dot product is already well-optimized** — `dotProductScalar` with
   unroll-by-8 + SSE4.1 target + `#pragma GCC ivdep` is near-optimal for this
   machine. The compiler already does aggressive vectorization.
3. **Branch cost > loop cost for small loops** — when the dot product is only
   2-8 iterations, the branch misprediction or switch dispatch costs more than
   the loop itself.
