## Phase 1: Fixes

### RTM-012: FLAC vendorLen integer overflow (one-line fix)
**File:** `AestraAudio/src/IO/MetadataParser.cpp:281-282`
**Change:** Added `if (vendorLen > blockSize - 4) continue;` before using vendorLen.
**Rationale:** Defense-in-depth. The 10MB block cap makes exploitation infeasible, but the bounds check costs nothing and closes the theoretical gap.

### RTM-006: Plugin cache integrity (mtime verification)
**File:** `AestraAudio/src/Plugin/PluginScanner.cpp`
**Changes:**
1. Cache format bumped to v2
2. On save: store each plugin file's `last_write_time` (64-bit) in the cache
3. On load: compare cached mtime with current file mtime. If mismatch → skip entry (needs rescan)
**Rationale:** An attacker who replaces a legitimate plugin binary would change the mtime. The cache detects this and refuses to use the stale entry, triggering a rescan of the modified file.

### RTM-008: Headless env var injection → CLI flag
**File:** `Source/App/HeadlessMain.cpp:698-706`
**Change:** `AESTRA_PROJECT` env var now prints a warning and is **ignored**. Users must use `--project <path>` instead.
**Rationale:** CLI flags are visible in CI logs (auditable). Env vars are silent (supply-chain risk). The `--project` flag already existed — we just removed the env var backdoor.

### RTM-007: Crash flag + autosave timestamp delta
**File:** `Source/App/AestraApp.cpp:479-505`
**Change:** Before showing the recovery dialog, compare crash flag mtime with autosave mtime. If delta > 5 minutes → discard both as possible pre-seeded attack.
**Rationale:** A planted attack requires creating both files. If they're not temporally consistent (written within the same session), it's an attack. Legitimate crashes have flag + autosave written seconds apart.

### RTM-005: Plugin first-load warning + trusted paths
**File:** `AestraAudio/include/Plugin/PluginScanner.h`, `AestraAudio/src/Plugin/PluginScanner.cpp`
**Changes:**
1. `isTrustedPath()` static method: classifies system paths (`/usr/lib/*`, Program Files, `/Library/*`) as trusted; user paths (`~/.vst3`, `~/Library/*`, custom) as untrusted
2. `FirstLoadWarningCallback` callback type: `std::function<bool(path, name)>`
3. `setFirstLoadWarningCallback()` method for UI to wire up
4. `m_seenUntrustedPlugins` set: prevents repeated prompts for the same plugin
5. In `scanDirectory()`: before adding a plugin from an untrusted path, invokes the callback if not yet seen. If callback returns false, the plugin is skipped.
**Rationale:** Covers the 90% case with minimal complexity. System paths auto-load (trusted). User paths prompt once (like browser extensions). The callback is optional — if not wired up, legacy behavior (load everything) is preserved.
