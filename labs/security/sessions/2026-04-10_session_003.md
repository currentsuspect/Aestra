## Hypothesis

All 4 remaining open vulnerabilities (RTM-013 through RTM-016) can be fixed with targeted changes that don't break existing functionality.

## Phase 1: Fixes

### Fix 1: RTM-013 — JSON parseNumber std::stod without try/catch
**File:** `AestraCore/include/AestraJSON.h:391-420`
**Changes:**
1. Pre-parse validation: reject empty strings, bare `-`, bare `.`, `-.`, trailing `e`/`E`/`+`
2. try/catch around `std::stod` → returns `JSON(0.0)` on failure

**Why it works:** The character-level parser loop can accept strings like `"1e"`, `"1e+"`, `"-."` that pass character checks but throw from `stod`. The pre-parse check catches structural issues; try/catch catches anything else.

### Fix 2: RTM-014 — JSON asArray()/asObject() mutable global static
**File:** `AestraCore/include/AestraJSON.h:40-63`
**Changes:**
1. Non-const `asArray()` now returns `std::vector<JSON>` by value (not reference)
2. Non-const `asObject()` now returns `std::map<std::string, JSON>` by value
3. Const versions still return const reference to a static empty container (safe because `const`)

**Why it works:** Callers who call the non-const accessor on a non-array/non-object get their own temporary copy. Modifications disappear at scope end — no cross-call contamination. Only 1 call site exists (`HeadlessMain.cpp:154`) and it's const, so no behavioral change.

### Fix 3: RTM-015 — Silent autosave on recovery fallback
**File:** `Source/App/AestraApp.cpp:518-530`
**Changes:** When RecoveryDialog is unavailable, **discard** the autosave file instead of silently loading it.

**Before:**
```cpp
// Fallback: silently load autosave (vulnerable to pre-seeded attack)
m_projectPath = autosavePath;
auto result = loadProject();
```

**After:**
```cpp
// [SEC-RTM-015] Discard autosave — don't silently load untrusted data
std::filesystem::remove(autosavePath, ec);
m_recoveryHandled = true;
```

**Trade-off:** If RecoveryDialog is somehow unavailable during a real crash, the user loses their autosave. This is preferable to silently loading an attacker's project. The dialog should always be available in normal operation.

### Fix 4: RTM-016 — Headless env var strtod silent failure
**File:** `Source/App/HeadlessMain.cpp:628-637, 686-694`
**Changes:** Both occurrences of `std::strtod(env, nullptr)` replaced with:
1. `endptr` check: `end == env` (no digits consumed) or `*end != '\0'` (trailing garbage) → reject
2. `std::isfinite(val)` check: reject `nan`, `inf`, `-inf`
3. Log warning with the offending value
