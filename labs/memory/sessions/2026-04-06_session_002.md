## Key Observations

1. **Buffer alignment matters** — `new uint8_t[]` only guarantees 16-byte alignment.
   To support 32-byte (AVX) and 64-byte alignments, the arena allocates
   `capacity + 63` bytes and aligns the start pointer to 64 bytes.
2. **CAS loop is simple and correct** — the bump allocator's atomic CAS loop
   handles concurrent allocations from multiple threads. Peak tracking uses
   a separate CAS loop for monotonic updates.
3. **No per-allocation locks** — the arena uses only atomic operations.
   `reset()` is the only non-thread-safe operation (by design — called from
   idle/UI thread when audio thread is quiescent).
